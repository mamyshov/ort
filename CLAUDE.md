# Платформа онлайн-курсов (клиентский проект)

Своя платформа вместо связки ClickFunnels и отдельного кабинета. Заказчик: знакомый, у которого курсы английского языка (DAS Education). Полное ТЗ: https://claude.ai/code/artifact/96b4070c-608b-4231-b975-664e1911901f — при расхождении с этим файлом верить ТЗ и сообщить о расхождении.

## Стек

- Next.js (App Router) + TypeScript + Tailwind. Один проект для публичных страниц, кабинета ученика и админки.
- База: обычный PostgreSQL 14+ (без Supabase), миграции в `db/migrations/`. Вход свой: пароли scrypt, сессии в таблице `sessions` (в базе хранится sha256 токена), cookie httpOnly. Запросы пользователя идут в транзакции с `app.user_id` и ролью `authenticated`, поэтому RLS действует и при ошибке в коде.
- Три языка интерфейса: русский (по умолчанию), кыргызский, английский. Библиотека next-intl, тексты в `messages/{ru,ky,en}.json`.
- Видео: Bunny Stream. Источник видео сменный (`lessons.video_provider`), YouTube и Vimeo остаются запасными вариантами.
- Шрифт Inter подключён из пакета `@fontsource-variable/inter` (не из Google Fonts): нужна кириллица, включая буквы Ң, Ү, Ө.
- ИИ: ключ только на сервере, суточный лимит запросов на ученика (`ai_usage`).

## Роли

`student`, `manager`, `teacher`, `owner`. Права записаны в правилах RLS в миграции и проверяются тестом `npm run test:db`.

- Владелец: всё.
- Менеджер: ученики, доступ, платежи и возвраты, лиды и сообщения, статистика. Курсы не правит, работы не видит.
- Преподаватель: только свои курсы (таблица `course_teachers`), проверка работ, прогресс своих учеников.
- Любое сотрудническое действие пишется в `audit_log`.

## Правила работы

- Права проверяются на сервере и в правилах базы, а не только скрываются в интерфейсе. Любая новая таблица сразу получает `enable row level security` и политики, и под них добавляется проверка в `db/tests/rls.test.mjs`.
- Платежи, записи лидов из форм и учёт ИИ пишутся только серверным подключением владельца (`service()` в `src/lib/db.ts`). Оно никогда не попадает в браузерный код.
- Платёж провайдера записывается один раз (уникальность `method + provider_ref`). Доступ ученику открывается только после статуса `paid`.
- Письменные задания проверяет ИИ сразу после отправки (оценка и разбор сохраняются, урок засчитывается от 50%; решение владельца). Если ИИ недоступен, работа ждёт преподавателя. Сертификат выдаёт только человек. Проверенное ИИ отличается тем, что `ai_draft` заполнен, а `reviewed_by` пуст.
- Ответы ИИ о курсе строятся только по материалам курса. Ученик видит пометку, что отвечает ИИ.
- Тексты на кыргызском от ИИ или машинного перевода проверяет живой человек до публикации.
- Мобильный вид основной: ученики заходят с телефона.
- Строки интерфейса только через `messages/*.json`, без текста в компонентах.
- Секреты не коммитить. Шаблон переменных: `.env.example`.

## Команды

- `npm run dev` — запуск для разработки.
- `npm run db:start|stop|reset|migrate|seed` — локальная база на порту 54329 и демо-данные (student@demo.local / demo12345; также owner, manager, teacher1 с тем же паролем).
- `npm run build` — сборка.
- `npm run lint` — проверка кода.
- `npm run test:db` — проверка миграции и правил доступа на PostgreSQL в памяти.

## Что сделано

- Основа, три языка, вход/выход, смена и сброс пароля.
- Кабинет ученика: курсы, прогресс, уроки, видео со сменным источником, поиск, профиль, практика с ИИ.
- Админка по ролям: курсы, модули, уроки, преподаватели, ученики и доступ, журнал действий, работы на проверку, сертификаты, платежи с возвратами, лиды и очередь сообщений.
- Экзамены двух видов (тест с проверкой на сервере, задание с проверкой преподавателя) и сертификаты с публичной страницей проверки.
- Воронка: вебинар → лид → сообщения и напоминания → предложение с серверным таймером скидки → заказ → оплата → допродажа $20.
- Оплата: общий путь `settlePayment` (повтор безопасен), способы: тестовый (только разработка), переводы ЭЛСОМ/Kaspi с автоподтверждением, ручное подтверждение. Finik — заготовка.
- Сообщения: очередь, WhatsApp/Telegram/почта, пробная отправка в разработке. Пиксель Facebook.
- Детские кабинеты: родитель заводит ребёнка (`profiles.guardian_id`, без почты и пароля), открывает его кабинет из своего аккаунта, возврат к родителю по паролю. Покупает только родитель (платёж с `user_id` ребёнка). ИИ в детском кабинете получает правила безопасности (`CHILD_RULES`).
- ИИ (11 функций): продающий помощник, собеседник, помощник по уроку, карточки, план недели, тест уровня, черновик проверки, вопросы к тесту, подсказка по лиду, сводка владельцу, перевод. Лимиты в `ai_usage`.
- Проверено в браузере сценариями по ролям (вход, кабинет, админка, экзамены, воронка, ИИ) и тестом правил базы.

## Известные ограничения и долги

- Тестовая оплата и пробная отправка сообщений включаются только при локальном `SITE_URL` или вне production.
- `npm audit` показывает уязвимости только в инструментах разработки (eslint-config-next, пакет braces). В рабочий код они не попадают. Принудительное исправление понижает версию eslint-config-next, поэтому не применялось.
- В `next.config.ts` убраны опции `cacheComponents` и `partialPrefetching`, которые добавил шаблон `create-next-app`: они меняют правила кэширования и не нужны на старте. Вернуть, если понадобятся.
- Данные старого кабинета не переносятся: платформа стартует с нуля.
